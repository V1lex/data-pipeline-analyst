### Реальный код

- Общего LLM-клиента, API, моделей БД, миграций и перечислений статусов хранения пока нет.

### Существующие контракты

Канонические исходники формального модуля находятся в ветке `tla_tlc`:

- `formal_check/src/models/input.py`: `variables / initial / transitions / properties`, типы `invariant`, `forbidden_state`, `reachable`, `deadlock_free`.
- `formal_check/src/models/output.py`: модели `PROPERTY_HOLDS`, `PROPERTY_VIOLATED`, `MODEL_INVALID`.
- `formal_check/src/models/models.py`: отдельные технические статусы runner: `success`, `infrastructure_error`, `timeout`.

Технический `success` не доказывает общий `PROPERTY_HOLDS`; до появления парсера генератор не должен подменять его собственным заключением. Нельзя также объявлять все ответы из приложенного промпта уже реализованными.

### Схемы и требования, ещё не ставшие кодом

- `database_schema.png`: PostgreSQL, таблицы `projects`, `messages`, `specifications`, `verification_runs`, `property_results`, `artifacts`. Значения enum не указаны.
- `sequence.png`: backend, аналитик, Validator, PostgreSQL и отдельный worker TLC; очередь в PostgreSQL через `FOR UPDATE SKIP LOCKED`.
- По приложенному описанию код генерируется LLM после общего `PROPERTY_HOLDS`, сохраняется как артефакт конкретной версии. Проверка модели не является проверкой Python или реальных данных.
- Пользователь сообщил о договорённости использовать Gemini вместо недоступного sandbox. Модель и интерфейс конфигурации пока не выбраны, реальных вызовов не было.

### Несовпадения и открытые решения

1. Сфера T22/T24 всё ещё описывает шаблоны и каталог операций; предоставленное описание фиксирует более поздний LLM-подход. Требуется явно актуализировать постановку, сохранив основание изменения.
2. T23 назначает Дмитрию создание всего модуля хранения, а описание требует не дублировать работу Вани. Готового storage нет. Граница вынесена пользователю на подтверждение.
3. Шесть таблиц не определяют способ сохранения неизменяемого снимка согласованных требований и границы сообщений для версии. Нужен совместимый механизм, предложенный до изменения схемы.
4. Схема не показывает, где хранить полный общий результат проверки, включая TIMEOUT/ошибки без `property_id`. Не создавать вымышленные результаты свойств; согласовать отображение с backend и формальным модулем.
5. ENUM БД, формат ошибок генератора, повторная генерация и защита от одинаковых параллельных запросов ещё требуют конкретного контракта.

Предлагаемое направление, не согласованное решение: выделенный Python-модуль генератора, небольшой заменяемый интерфейс LLM, адаптер Gemini, PostgreSQL и тестовый клиент для независимой проверки. Диалоговый аналитик остаётся задачей Андрея.
