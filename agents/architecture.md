### Несовпадения и открытые решения

1. Сфера T22/T24 всё ещё описывает шаблоны и каталог операций; предоставленное описание фиксирует более поздний LLM-подход. Требуется явно актуализировать постановку, сохранив основание изменения.
2. T23 назначает Дмитрию создание всего модуля хранения, а описание требует не дублировать работу Вани. Готового storage нет. Граница вынесена пользователю на подтверждение.
3. Шесть таблиц не определяют способ сохранения неизменяемого снимка согласованных требований и границы сообщений для версии. Нужен совместимый механизм, предложенный до изменения схемы.
4. Схема не показывает, где хранить полный общий результат проверки, включая TIMEOUT/ошибки без `property_id`. Не создавать вымышленные результаты свойств; согласовать отображение с backend и формальным модулем.
5. ENUM БД, формат ошибок генератора, повторная генерация и защита от одинаковых параллельных запросов ещё требуют конкретного контракта.

Предлагаемое направление, не согласованное решение: выделенный Python-модуль генератора, небольшой заменяемый интерфейс LLM, адаптер Gemini, PostgreSQL и тестовый клиент для независимой проверки. Диалоговый аналитик остаётся задачей Андрея.

## Реализация T22–T26 — продолжение 2026-10-30

Пользователь указал следовать явно назначенным задачам. Поэтому реализована вся T23, без повторного перераспределения ролей; аналитик Андрея и backend Вани не создавались в этой ветке.

### Доступные модули

- `src/pipeline_generator/storage.py`: проекты, сообщения, версии, согласование, история, очередь и полные результаты проверок. PostgreSQL, без ORM и SQLite.
- `migrations/001_initial.sql`: шесть таблиц; явные дополнительные поля `specifications.context_json`, `verification_runs.result_json`. Значения статусов и артефактов заданы CHECK-ограничениями. Это конкретный вариант для интеграции backend, не скрытое изменение чужой схемы.
- `models.py`, `generator.py`, `generation_prompt.md`: генерация без каталога операций, точный снимок контекста и строгий разбор ответа.
- `llm.py`, `gemini.py`: заменяемый LLM-интерфейс и REST-адаптер официального Gemini API.
- `issuance.py`, `service.py`: ключ идемпотентности, короткая резервация, LLM без удержания соединения, повторная проверка версии и атомарное сохранение `.py` вместе с manifest.

Канонические документы: `docs/generator_contract.md`, `docs/integration.md`. Для запуска и проверок — README, `examples/README.md`, `docs/validation.md`. Модель DSL Кирилла сохранена без генераторных дополнений и не скопирована как собственный Validator.

### Привязка и хранение

Модель, требования, выбранные сообщения и окружение фиксируются в неизменяемом снимке версии. Версия получает собственные запуски; только последний завершённый общий `PROPERTY_HOLDS` от TLC разрешает генерацию. В постановку запроса явно включается этот снимок, а не текущий чат.

Ключ запроса фиксирует одну попытку. Состояние попытки хранится в `artifacts` как `generation_manifest`; код — отдельный `pyspark`-артефакт с UUID в имени. Повтор возвращает сохранённый файл, новая попытка сохраняет отдельный. При аварии процесса не выполняется скрытый повтор: после срока попытки требуется новый ключ.

Полный ответ проверки хранится в запуске; `property_results` получает только явно названное нарушенное свойство. `ENGINE_ERROR` и `INFRASTRUCTURE_ERROR` сохраняются как исходные разные имена и оба блокируют выдачу.

### Проверки и границы готовности

65 основных тестов проходят с реальным PostgreSQL, в том числе чтение из нового Python-процесса, конкурентные повторы и откат записи. Независимое ревью основного модуля выполнено; две ошибки формата ответа исправлены через воспроизводящие тесты.

Пользователь предоставил тестовый ключ, указал считать его рабочим и попросил локальный `.env`. Файл создан с правами 0600, игнорируется Git; код читает его явно через `from_environment(env_file=...)`. Значение не записано в отслеживаемые файлы.

Фактический минимальный вызов Google вернул HTTP 400 / FAILED_PRECONDITION: место выполнения не поддерживается API. Успешной генерации пока не было; вопрос локации пользователь взял на себя. Платного fallback нет.

Два ручных образца не выдаются за LLM-результат; их отдельные Spark-проверки и запуск настоящего ответа модели имеют собственную готовность. Полная интеграция API/UI и парсер TLC остаются внешними точками подключения.
