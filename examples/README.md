# Синтетические примеры

`revenue_reference.py` и `sensor_reference.py` написаны вручную для проверки окружения и ожидаемых чисел. Они не являются результатами Gemini. Контексты `*_context.json` используют искусственный `PROPERTY_HOLDS` со статистикой 0: это тестовые данные, не отчёт настоящего TLC. Их нельзя записывать в production как подтверждение проверки.

## Пример 1 — выручка по городам

- `data/orders.csv`: `(A,2,Москва)`, `(A,1,Москва)`, `(B,3,Казань)`.
- `data/prices.csv`: `(A,100)`, `(B,50)`.
- Все указанные поля обязательны, товар в ценах уникален. Ошибки останавливают обработку до сохранения.
- После обеих независимых проверок — inner join; отсутствие цены исключает заказ.
- `quantity * price`, затем сумма по городу. Новое Parquet-назначение без перезаписи.
- Ожидается Москва = 300, Казань = 150; порядок строк не важен.

## Пример 2 — датчики

Строки с пустым датчиком или температурой отбрасываются по явно заданному правилу этого примера. Отрицательная температура допустима. Среднее и число оставшихся измерений: north = `(15.0, 2)`, south = `(-5.0, 1)`. Этот сценарий использует фильтрацию и среднее, без объединения таблиц.

## Явный запуск ручных образцов

PySpark 3.5.8 выбран как конкретное тестовое окружение; он поддерживает Python 3.8+ и Java 8/11/17. Для этой практики используется Python 3.12. [Официальные требования Spark](https://spark.apache.org/docs/3.5.8/).

```sh
uv sync --extra dev --extra spark
RUN_SPARK_TESTS=1 uv run pytest -m spark -q
```

Шесть проверок запускают только просмотренные ручные образцы на маленьких данных: два положительных сценария, три ошибки данных и запрет перезаписи. Обычный запуск тестов их не включает. Это инструменты разработки, не модуль исполнения произвольного кода.

Для отдельного ручного запуска:

```sh
uv run spark-submit --master 'local[1]' examples/revenue_reference.py \
  --orders examples/data/orders.csv --prices examples/data/prices.csv --output /tmp/revenue-new
uv run spark-submit --master 'local[1]' examples/sensor_reference.py \
  --readings examples/data/readings.csv --output /tmp/sensors-new
```

Выберите ещё не существующие выходные каталоги. Скрипты не перезаписывают назначения.

## Настоящая генерация Gemini

После настройки локального `.env` и доступности API из места запуска:

```sh
uv run python examples/generate_live.py \
  --env-file .env --context examples/revenue_context.json \
  --output-dir generated-revenue --acknowledge-synthetic-verification
uv run python examples/generate_live.py \
  --env-file .env --context examples/sensor_context.json \
  --output-dir generated-sensor --acknowledge-synthetic-verification
```

Это явный разработческий вызов генератора с искусственным результатом проверки, не полный продуктовый сценарий. Скрипт сохраняет настоящий ответ модели и происхождение рядом с файлом; автоматически полученный Python не запускает. Перед запуском полученный файл нужно просмотреть, затем вручную выполнить через `spark-submit` с путями синтетических CSV и новым Parquet-назначением. Сравните числа с ожидаемыми выше и повторите проверки ошибок данных.

Только запуск именно полученного от модели файла подтверждает соответствующую часть T26. Успех ручных образцов или fake-клиента не заменяет этот шаг.
