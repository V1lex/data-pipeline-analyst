# Пример преподавателя: приёмка файла

В разделе «Файлы → Приёмка файла» реализован отдельный фиксированный сценарий. При первом обращении укажите технический ID, выберите загруженный файл и хотя бы одну обязательную колонку. Приложение проверит каждую строку: выбранные колонки должны существовать и содержать непустые значения. Пустой файл считается ошибочным. Результат и пройденный путь записываются в БД проекта. Для повторного обращения можно указать тот же ID без файла.

По условию примера повторный ID сразу получает статус успеха, даже если исходная проверка завершилась ошибкой: такой статус означает, что файл уже загружался, а не что его данные корректны. Интерфейс показывает предупреждение и сохраняет предыдущие ошибки. Новый файл с тем же ID, но другим содержимым, отклоняется как конфликт. Транспорт внешних уведомлений в примере не задан: статус хранится локально и доступен через API, но наружу не отправляется.

Это не конструктор произвольных процессов и не выполнение PySpark-кода. Загрузка файла в диалог и приёмка по техническому ID — отдельные действия. Для интеграции с внешней системой нужны её протокол, адрес и бизнес-правила, которых в примере нет.

`model.json` — формальная абстракция этого сценария для TLC. Её можно проверить через `PYTHONPATH=backend/src python -m compiler.formal_check.src.main examples/file-ingestion/model.json --timeout 60` при установленных Java и `TLC_JAR_PATH`. Проверяются достижимость трёх итогов, отсутствие проверки на ветке повтора и отсутствие ошибок до проверки. Проверка абстрактной модели сама по себе не доказывает корректность реализации Python; её поведение дополнительно проверяется тестами.
