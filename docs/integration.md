# Интеграционный контракт MVP — 01.11.2026

Канонический контракт данных — `backend/src/pipeline_spec`. Аналитик, API, worker и генератор используют одну установленную сборку backend, PostgreSQL и цепочку Alembic. Корневой uv workspace устанавливает backend; отдельного пакета `src` нет.

## HTTP

Все пути начинаются с `/api/v1`.

| Метод / путь | Результат |
| --- | --- |
| GET /health | 200 только при доступной БД с таблицами |
| GET, POST /projects | список / создание проекта |
| GET /projects/{id} | сообщения, снимок диалога, история версий |
| POST /projects/{id}/messages | `content`; ответ, полнота и состояние аналитика |
| POST /projects/{id}/specifications/build | новая DRAFT-версия полного PipelineSpecification |
| GET /specifications/{id} | версия, запуски TLC, сохранённые файлы |
| POST /specifications/{id}/approve | согласование этой версии после валидации |
| POST /specifications/{id}/verify | 202 и UUID задания для worker |
| POST /specifications/{id}/generate | UUID `request_id`; текст LLM и код/метаданные файла |
| GET /specifications/{id}/artifacts/{artifact_id} | скачивание .py этой версии |

Публичного эндпоинта записи вердикта нет. Синхронные БД/LLM-вызовы FastAPI выполняет в thread pool. Ошибки имеют оболочку `error` с `code/message/retryable/details`, без DSN и ключей. Скачивание требует совпадающие spec_id/artifact_id; авторизация пользователей пока отсутствует, это локальный MVP.

## Сохранение и согласование

`projects.analyst_state` хранит историю, последний полный ответ, структурированный черновик, происхождение и согласование параметров. Короткий lease предотвращает параллельную запись одного диалога; соединение не удерживается во время LLM. Ошибка модели не сохраняет половину хода. При создании версии lease повторно проверяется внутри транзакции выделения номера версии: устаревший результат не привязывается к новой переписке.

Полнота требует валидный PipelineSpecification, корректные ссылки/DAG и согласованные параметры. Builder получает структурированный снимок. Источники, шаги, приёмники и заданные ограничения не могут молча отличаться от согласованного черновика.

`specifications` содержит формальный `spec_json` и неизменяемый `context_json` с требованиями, сообщениями, окружением и полной pipeline specification. SQL-триггеры запрещают изменение версии/снимка и завершённых результатов. Схемная версия JSON и номер версии требований — разные значения.

## Проверка

Worker забирает `QUEUED` через `FOR UPDATE SKIP LOCKED`, освобождает транзакцию, валидирует модель, компилирует в отдельную временную папку и запускает Java/TLC. Safety и каждое existential reachable проверяются отдельно; общий положительный статус возникает только после всех необходимых проверок. Прогресс, отсутствие ошибок в обрезанном выводе и технический код runner не заменяют завершение.

Нормализованный ответ сохраняется целиком в `verification_runs.result_json`. `property_results` содержит только реально известные результаты свойств. Ошибка/тайм-аут не становятся успехом. Жёсткий crash процесса требует нового запуска; lease/heartbeat для очереди пока нет.

## Генерация

`GenerationService` загружает сохранённую APPROVED-версию и последний FINISHED-результат с `PROPERTY_HOLDS`, `engine=TLC` и статистикой. Новый или незавершённый запуск блокирует генерацию. PySparkGenerator передаёт весь снимок LLM и валидирует оболочку `answer/content`, не выполняя Python.

`request_id` резервирует `generation_manifest` в artifacts до запроса модели. LLM вызывается без открытого соединения. Готовый .py и manifest публикуются атомарно после повторной проверки fingerprint. Повтор возвращает прежний результат, в том числе после перезапуска без настроенного Gemini. Известная FAILED-попытка не запускается снова с тем же UUID; UI создаёт новый UUID только на следующее явное действие. Неоднозначная сетевая ошибка сохраняет UUID для безопасного повтора.

Один SDK-клиент Gemini создаётся лениво и используется аналитиком, builder и генератором. Инициализация защищена от гонок; клиент закрывается владельцем приложения. LLM-данные не подменяются mock в рабочем API.

## Миграции

`python -m db.migrations` и `PostgresRepository.migrate()` запускают одну цепочку Alembic в заданной `DATABASE_SCHEMA`. Исходная ревизия `12a5814e76d1` сохранена; `20261101_mvp` добавляет контекст, полный вердикт, server defaults, согласованные текстовые статусы, immutable triggers и сохранение диалога. Legacy completed без сохранённого вердикта получает блокирующий ENGINE_ERROR, а не выдуманный успех.

Неверсионированная схема с существующими pipeline-таблицами отклоняется без изменений. Автоматическое stamp/adopt не выполняется. Обратная миграция MVP не обещает безопасно удалить снимки: используйте резервную копию. Миграции упакованы в wheel и проверены вне checkout.
